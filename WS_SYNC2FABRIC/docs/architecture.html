Two customer tables, one reporting table

A customer from Azure SQL (1, Jansen, A) and a customer from the local Win10 SQL Server (1, Pietersen, B) are loaded into a Fabric warehouse, enriched with T-SQL, and published as dwh.Customers. Every step is a script; one cleanup removes it all.

What each part does

Azure SQL (opendata.nl)

Serverless General Purpose, 0.5 vCore minimum, pauses after 60 minutes idle. Scripts reach it with your Entra token; the read-only login fabric_reader is kept for a future Fabric connection.

Local SQL Server

Already installed on this PC. Fabric cannot reach it from the cloud, so the gateway relays the copy over an outbound connection. No inbound firewall change. The gateway signs in with the read-only SQL login fabric_local_user; Windows authentication failed to impersonate the user here.

Loading the staging tables

The Azure row is read by the script and inserted into the warehouse. A warehouse COPY cannot read Azure SQL directly without a staging store, which is too much for one row. The local table goes through a pipeline and the gateway, with staging enabled because the warehouse COPY command cannot read a SQL Server source directly. Both loads truncate first, so a rerun never duplicates rows.

Warehouse db1

Schemas stg (raw copies) and dwh (reporting). Both sources use CustomerId 1, so enrichment adds a surrogate CustomerKey and a SourceSystem column.

Decisions you inherit

No mirroring

Mirroring needs the SQL server's managed identity to be a member of the Fabric workspace. Azure sits in the opendata.nl tenant and Fabric in onmicrosoft.com, so Fabric cannot find that identity. Reading with a token from the script works across tenants.

Two logins

Azure calls use the opendata.nl account. Fabric calls use the tenant-level account for onmicrosoft.com, selected by tenant id so az does not pick the wrong cached token.

Germany West Central

West and North Europe refused new SQL servers on this subscription. The region does not matter to Fabric.

Secrets

Generated passwords live only in .secrets/state.json. That folder and config.ps1 are in .gitignore.
